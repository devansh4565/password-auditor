# Product

## Platform

web

## Stack

React + Vite + Tailwind CSS + Motion (frontend, Firebase Hosting); FastAPI (Python) backend on Render free tier; ML model trained offline in scikit-learn, exported to ONNX and run in the browser with onnxruntime-web. Confirmed by the user.

## Users

The public: anyone who opens the link to check how strong a password is, understand why, and learn how passwords should be stored. It is also evaluated as a university project (CSN 446 / CSF 446, Project 4), so every feature must work live, but the site addresses a general visitor rather than an examiner.

## Product Purpose

Password Strength & Secure Storage Auditor. It assesses password strength locally, detects common patterns, shows how attackers would actually crack a password, and demonstrates secure storage with a modern password-hashing algorithm (Argon2id, compared against MD5, SHA-256 and bcrypt). Success: a visitor leaves knowing whether their password is weak, why, and what good storage looks like.

## Positioning

Most strength checkers show a coloured bar. This one shows the mechanism: the same password attacked live by brute force, dictionary and hybrid rules, a real rainbow table cracking unsalted MD5, and a model trained on synthetic data giving a second opinion alongside zxcvbn.

## Operating Context

Visitors type passwords into the browser. Analysis, ML prediction, generation and the attack simulation run client-side; passwords typed into the analyzer are never sent anywhere. The backend handles only heavy demos (rainbow table lookup, server-side hash timing, bulk CSV audit with PDF report) and sleeps when idle on the free tier, so cold starts of 30-60s are expected.

## Capabilities and Constraints

- Pages: Analyzer, Attack Simulator, Hashing Lab, Rainbow Table, Bulk Audit, Generator, ML Lab.
- All training and audit data is synthetic, generated by project scripts. No real leaked password data is used, shipped or displayed.
- Attack timing uses published GPU hash-rate figures; the simulator simulates, it does not crack real targets.
- Rate limiting on backend hashing and audit endpoints (Argon2id is deliberately memory-hard; Render free tier has 512 MB RAM).
- Deadline: 10 November 2026.

## Evidence on Hand

No real users, testimonials, benchmarks or statistics exist. Never fabricate usage numbers or claims. Demonstration data is synthetic and must be labelled as such.

## Product Principles

1. Show the mechanism, not just the verdict.
2. The password never leaves the browser unless the visitor explicitly runs a server demo.
3. Every number is explainable: crack times state their assumed hardware and hash.
4. Educational, not alarmist: explain the fix next to every weakness.
