## What this is

Password Strength & Secure Storage Auditor ("Bombe"), CSN 446 / CSF 446 Project 4, DIT University.
Public, educational web app: analyse a password, watch it attacked (simulated), see how it should be stored.

- Live frontend: https://bombe-pw-auditor.web.app (Firebase Hosting site `bombe-pw-auditor` inside project `stockpilot-9sqqn`)
- Live API: https://bombe-password-auditor-api.onrender.com (Render free tier, Singapore, service `srv-dbf534rrjlhs73fhd9q0`)
- Deadline: 10 November 2026

Product truth lives in `PRODUCT.md`. Design rationale lives in `docs/`.

## Layout

```
frontend/   React 19 + Vite 6 + Tailwind 4 + Motion. All 7 tool pages.
backend/    FastAPI. Rainbow-table lookup, server hash timing, bulk audit + PDF.
ml/         Offline pipeline: synthetic data -> features -> RandomForest -> JSON export.
shared/     Artifacts produced by ml/build.py (model, markov, dictionary, wordlists, metrics, test vectors).
docs/       Architecture, HLD, LLD, API, ML, security, test plan, deployment.
```

## Commands

```bash
# ML (regenerates everything in shared/; ~1 min)
cd ml && python build.py
cp ../shared/*.json ../frontend/public/data/ && cp ../shared/{attack_wordlist,dictionary}.json ../backend/data/

# Rainbow table (only if rainbow.py's reduction or keyspace changes; ~3 min, multiprocess)
cd backend && python build_rainbow.py

# Backend
cd backend && pip install -r requirements.txt && uvicorn app.main:app --reload --port 8000

# Frontend
cd frontend && npm install && npm run dev        # http://localhost:5173, uses .env.local VITE_API_URL
cd frontend && npx tsc -b                        # typecheck
cd frontend && node scripts/parity.mts           # TS features must match Python features

# Deploy
cd frontend && npm run build && cd .. && firebase deploy --only hosting:bombe-pw-auditor --project stockpilot-9sqqn
git push   # Render auto-deploys backend from main
```

## Invariants (do not break)

1. **Feature parity.** `frontend/src/lib/features.ts` mirrors `ml/features.py` exactly. Any change to one must be made
   to the other, then `python ml/build.py` and `node frontend/scripts/parity.mts` must pass. Write JSON from Python with
   `encoding="utf-8"` (Windows defaults to cp1252).
2. **The visitor's password stays in the browser.** Analyzer, ML, Generator, Attack Simulator and Hashing Lab run
   client-side. Only the Rainbow Table (demo plaintext ≤5 chars) and Bulk Audit (uploaded CSV) talk to the server.
3. **Synthetic data only.** No real breach corpora anywhere: training data, attack wordlist and the audit sample are
   generated by project scripts. Never add a leaked-password list.
4. **The Attack Simulator simulates.** It steps candidates against the locally known password and reports time from
   published hash rates (`frontend/src/lib/rates.ts`). It must not become a tool for cracking real hashes.
5. **Every number is explainable.** Crack times state their hash and hardware assumption.
6. **Firebase deploys target only the `bombe-pw-auditor` site.** `firebase.json` pins `"site"`; never deploy the
   project's other site (`stockpilot-9sqqn`).

## Design system

Visual direction "Bombe Room" (see `.impeccable/surfaces/frontend-src-app-tsx.md`): black-lacquer shell, steel rails,
one drum-ring hue per tool (`--color-t-*` in `frontend/src/index.css`), Figtree for UI, JetBrains Mono for data.
Signature: the drum row (`components/Drum.tsx`). Text on the attack/hashing hues uses `--on-tool` (ink) for contrast.

## Conventions

- TypeScript strict; no unused locals (tsc fails the build).
- slowapi requires the endpoint parameter to be named `request`.
- Backend rate limits: `/hash` 30/min, `/rainbow/lookup` 60/min, `/audit*` 20/min, uploads ≤400 KB / 500 rows.
- Render free tier sleeps after ~15 min idle; first request takes 30-60 s. UI copy already says so.
